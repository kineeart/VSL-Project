AUGMENTATION ANALYSIS
═════════════════════════════════════════════════════════════════════════════════

WHY AUGMENTATION?
------------------
In sign language recognition, augmentation helps the model become robust to:
1. Different hand sizes (both signers and within same signer)
2. Different camera distances/zoom levels
3. Different body positions relative to camera
4. Lighting and environmental variations

AUGMENTATION STRATEGIES COMPARED:
----------------------------------

1. ORIGINAL (No augmentation)
   Scale factor: 1.0 (baseline)
   Description: Raw keypoints from video with no modifications

2. AUGMENTED (Scale augmentation)
   Scale factor: Random in [0.8, 1.2]
   - 0.8x: Shrinks all keypoint coordinates by 20%
   - 1.2x: Extends all keypoint coordinates by 20%
   Description: Uniformly scales coordinates around center to simulate zoom/distance variation

HOW AUGMENTATION WORKS:
-----------------------
1. Calculate bounding box of all keypoints
2. Find center of bounding box
3. Scale each coordinate: new_coord = center + (coord - center) × scale_factor
4. Result: Preserves relative spatial relationships while changing scale

3. Gesture Coverage: What portion of the grid is used?
4. Scale Effects: Does augmented version show obvious size changes?
5. Relative Positions: Are hand-to-body relationships preserved?

COMPARING KEYPOINT PATTERNS:
-----------------------------
Original side shows: Natural signing pattern from video
Augmented side shows: Same sign at different scale

If augmentation is working correctly:
- Left and right images should show similar shapes
- Right image points should be closer together (scaled down) or spread apart (scaled up)
- Relative distances between keypoints should be maintained

NORMALIZATION SCHEME
═════════════════════════════════════════════════════════════════════════════════

The model uses per-feature normalization:

For each of 1662 features:
1. Calculate mean across all training samples
2. Calculate standard deviation across all training samples
3. During inference: normalized_feature = (feature - mean) / std

Parameters stored:
- norm_mean.npy: 1662 mean values
- norm_std.npy: 1662 std values

This ensures consistent feature distributions across different signers and environments.

TECHNICAL NOTES
═════════════════════════════════════════════════════════════════════════════════

Frame Representation:
- Visualizations show MEAN across all frames in sample sequence
- This provides stable representation of gesture pattern
- Individual frame variations would be too noisy

Visualization Method:
- Each preview is embedded as base64-encoded PNG in HTML
- File size is optimized for quick loading
- High DPI (100) used for clarity

Coordinate normalization in visualizations:
- X: [0, 1] from left to right
- Y: [0, 1] from top to bottom (note: Y is inverted from typical image coords)
- All points are plotted in this normalized space

COMMON QUESTIONS
═════════════════════════════════════════════════════════════════════════════════

Q: Why are some keypoints missing?
A: Missing points appear when confidence is too low or point is not detected.
   This is normal for face mesh in profile views or partially visible poses.

Q: Why does the augmented version look very small/large?
A: Augmentation applies random scale in range [0.8, 1.2]. Shows at different zoom levels.

Q: All classes use the same sample data?
A: Yes, to ensure fair comparison. Same keypoint sequence is used for all 15 classes.
   This shows augmentation effects consistently across classes.

Q: How do I use these visualizations for my project?
A: Use as reference to understand:
   - Expected gesture patterns for each class
   - How augmentation affects keypoints
   - Data distribution and normalization
   - Quality of keypoint detection
